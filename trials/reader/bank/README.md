# Item bank for the path-prediction reader experiment

Built on 2026-11-14 from the real history of two repositories, read-only. `build.py` regenerates
every JSON file from `git log`, `git diff-tree`, `git cat-file` and `git merge-base`. It exits
non-zero when a commit binds to no Change or to two, when an item has no answer path or more than
40, when a motivation has fewer than two or more than five sentences, or when a motivation holds a
word that is a path component of its answer or a piece of one.

## What a subject may see

Only the `id` and `motivation` of one entry of `<repo>-items.json` or
`<repo>-items-product-only.json`. Those files hold `id`, `motivation` and `size`, and no Change
name. `size` is the number of answer paths; show it only if the protocol means to.

Every other file holds answers: `<repo>-answers.json`, `<repo>-excluded.md`, `build.py`, this file
and the three `aigw-cli-v0.7.0-*` files.

## How the commit ranges were found

Every commit in `<pin>..dev` that is not a merge is bound to exactly one Change, and `build.py`
asserts it:

- A commit that adds or edits a file under one Change's directory belongs to that Change. No commit
  touches two.
- AIGW CLI: every commit that touches no Change directory names its Change in a `Change <name>.`
  trailer. No commit is bound by hand.
- ETHOS: commit bodies carry no trailer. Sixteen commits touch no Change directory and are bound by
  hand in `build.py`: each is cited by hash in that Change's `tasks.md`, or its subject names the
  Change's object (the plan section, DR-0025's index entry).
- A commit belongs to the first archive of its Change's name that descends from it. This matters
  once: `peer-identity-scrub` was made and archived on a side line on 2026-11-07, and made again on
  the main line and archived on 2026-11-12.

ETHOS is linear after its pin, 115 commits. AIGW CLI after `v0.6.1` has 444 commits and four
merges, each `chore: merge candidate contribution`; commits are walked in topological order.

- The merges belong to no Change. Three resolve a conflict (`internal/cli/app.go` in `5a543f8e`,
  `CHANGELOG.md` in `1fc62139`, `internal/store/team_test.go` in `81a7e4e2`); no answer counts a
  merge's own diff.
- The pin is the second parent of `5a543f8e`. `redundancy-removal` branched six commits before the
  pin, so "after the pin" means reachable from `dev` and not from the pin.
- Nine commits serve `gitlab-peer-reconciliation`, which is still active on `dev`.

In `<repo>-answers.json`, `commits` is the first and last commit of the Change. Where
`range_holds_other_changes` is true that span also holds other Changes' commits, so
`change_commits` gives the exact list and `implementing_commits` those that touch an answer path.

No ETHOS Change directory exists at its pin. At the AIGW CLI pin `secret-prompt-echo` is active and
already implemented; it is excluded.

## What an answer holds

`answer_paths` is every path changed in the Change's commits, read with `--no-renames`, minus
`openspec/changes/`, `CHANGELOG.md`, lock files (`uv.lock`, `package-lock.json`, `go.sum`,
`*.lock`) and the projected CI files (`.gitlab-ci.yml`, `.github/workflows/`). `answer_dirs` is each
path's parent directory cut to three components; a file at the root gives `.`.

Extra fields let a scorer narrow the key without rebuilding it:

- `incidental_paths`: canonical specs under `openspec/specs/` that the archive commit merged (17 of
  the 20 items), and four digest manifests in `ethos-03`. They count in `size`; the motivation is
  unlikely to lead a subject to them.
- `paths_created_by_this_change`: new files, which a subject can name only by guessing.
- `paths_created_by_an_earlier_change_after_the_pin`: files that do not exist at the pin and that
  this Change edits (two paths in `ethos-08`, none in AIGW CLI).
- `paths_absent_at_dev`: one path in `ethos-06`, created by the Change and merged away later.
- `kind`: `product`, `tests-only` or `acceptance-tooling`.

## Motivation check

Each motivation is three to five sentences. `build.py` compares its words with every component of
the item's answer paths, with and without the extension (`motivation_strict_hits`), and with the
pieces of each component split at `_`, `-` and `.`, singular and plural folded
(`motivation_soft_hits`). Both lists are empty for all 20 items.

`motivation_words_that_are_some_file_stem_at_the_pin` lists words that equal the stem of some file
anywhere in the repository, such as `commit`, `rule`, `proof` or `list`. None is part of the item's
answer; they are ordinary words and were left in.
